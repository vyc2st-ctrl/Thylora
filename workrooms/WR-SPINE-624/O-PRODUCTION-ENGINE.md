# O · Production Engine

The rule every department follows before anything reaches the Chairman.

## 1 · The loop

1. **Receive** — the request is stored verbatim (`chairman_source_messages`, hash-chained) and atomized
   (`chairman_source_segments` + `thylora_response_point_coverage`). Coverage must reach Cq = 1.00.
2. **Assign** — each atom goes to one workroom (`thylora_department_workroom_v1`); work not done now becomes a work item
   with one of NOW / QUEUED_WITH_DEPENDENCY / HOLD_FOR_EVIDENCE / APPROVAL_REQUIRED plus owner, blocker, release condition, next action.
3. **Develop three treatments** when the request has more than one honest way to be answered. Each treatment carries:
   people · world place · visual (spec only until the Shared-Vision gate `MATH-SHARED-VISION-622` passes, min(S,I,G,C) ≥ 4) ·
   script/copy · math (Math Display Law) · evidence · production method · cost (or UNKNOWN with basis) · money path ·
   help path · Earth path · rights · blockers · next action.
4. **Recommend** one, and say why.
5. **Present** — the Chairman chooses among developed options. The Chairman is never asked to build the department's work.

## 2 · When one treatment is enough

A request with one correct answer (a test, a migration, a verified fact, a recipe with a documented method) gets one
deliverable, not three invented alternatives. This run applied three treatments where a real choice exists
(Court Request 001) and single deliverables elsewhere.

## 4 · Gate before presentation (checklist)

- [ ] Source stored and Cq = 1.00
- [ ] Every person named is existing (with backend code) or marked PROPOSED
- [ ] Every number has units in both systems or is marked unitless; every formula has a class
- [ ] Every unknown is written UNKNOWN
- [ ] Money path and help path stated, or "none" stated
- [ ] Every open item carries the four-way classification
- [ ] Restart point written

## 5 · Restart point

For any new request: store verbatim → atomize → assign → (3 treatments if a real choice exists) → recommend → present.
